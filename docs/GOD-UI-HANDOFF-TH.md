# GOD → J · ส่งต่องาน UI ของ RalphLAB

21 พฤศจิกายน 2026 · สำหรับ J (UI), ก็อต (ระบบงานส่วนที่ 1), พี่โอ๊ตและพี่แตม (ทดสอบและเชื่อม LINE)

**แนะนำให้ J เริ่มที่ใบงานติดตามตามเวลา** ผู้ใช้ควรเปิดใบงานแล้วตอบได้ทันทีว่า “กำลังติดตามอะไร รอบถัดไปเมื่อไหร่ ใครต้องทำอะไร และผลล่าสุดมาจากไหน” เส้นทางนี้มีทั้งแบบฟอร์ม ข้อมูลรายรอบ หลักฐาน คำตัดสิน และรายงานให้ต่อ UI ได้ทันที [เปิดหน้าติดตามตามเวลา](https://ralphlab-workbench.surawit2003it.chatgpt.site/lab-room/timed)

## 1. เปิดงานให้ถูกที่

| ต้องการดูอะไร | เปิดที่ไหน | ขอบเขตที่มี |
|---|---|---|
| ห้องรวมของทีมในแอป Next.js | `/lab-room` หรือแท็บ Lab ใน Studio | ห้องและแชตของ `main` มีกราฟโครงการและคำถามรอคำตอบ เมนู **ใบงานและโต๊ะทดลอง** พาไปส่วนที่ GOD เพิ่ม |
| ใบงานทุกประเภทในแอป Next.js | `/lab-room/orders` | เลือกโครงการ เริ่มจากโจทย์ เปิดใบงานเดิม แนบสูตร อ่านรายงาน เจ้าของจัดการสิทธิ์อ่านได้ |
| สถานีทดสอบสูตรในแอป Next.js | `/lab-room?table=station` | เลือกโครงการและรุ่นสูตรที่มีผลประเมิน ดูผลรายด้านและตัดสินใจเก็บหรือทิ้งตัวอย่าง |
| โปรตีนที่เปิดดูได้บนเว็บสาธารณะ | [ดูโครงสร้าง 3D](https://ralphlab-workbench.surawit2003it.chatgpt.site/lab-room/protein) · [วางงานบนโต๊ะ](https://ralphlab-workbench.surawit2003it.chatgpt.site/lab-room?table=protein) | หน้าดูโครงสร้างเปิดได้โดยไม่ล็อกอิน การผูกงานกับโครงการหรือบันทึกผลต้องมีบัญชี |
| ใบงานบนเว็บ Cloud | [ใบงานโต๊ะโปรตีน](https://ralphlab-workbench.surawit2003it.chatgpt.site/lab-room/orders) · [ใบงานตามเวลา](https://ralphlab-workbench.surawit2003it.chatgpt.site/lab-room/timed) | Cloud ใช้หน้าโปรตีนเฉพาะทางที่เส้นทาง `/lab-room/orders` ตัวเลือกงานวิจัยหกประเภทอยู่ในหน้า Orders ของ Next.js |
| ทีม Agent บน Cloud | [ทีมนักวิจัย](https://ralphlab-workbench.surawit2003it.chatgpt.site/lab-room/team) | เลือกใบงานและบทบาท ดูผลเครื่องมือ หรือส่งงานให้ OpenAI เมื่อผู้ดูแลตั้งค่าบริการแล้ว |

**ตัวระบุใบงานต่างกัน** งานบนโต๊ะโปรตีนเปิดด้วย `?project=…&order=…` ใบงานตามเวลาใช้ `/lab-room/timed?id=…` และเปิดทีมของใบนั้นด้วย `/lab-room/team?study=…` ให้ปุ่มกลับและปุ่มคัดลอกใช้ลิงก์ของใบงานที่เปิดอยู่ เว็บเป็น Public แต่ข้อมูลใบงาน Cloud ผูกกับบัญชีเจ้าของ

## 2. หน้าจอและงานที่ส่งให้ J

| ตำแหน่งบนจอ | GOD ทำ UI และระบบอะไรไว้แล้ว | งาน UI ที่ J ทำต่อได้ |
|---|---|---|
| **ห้อง 3D และการเลือกงาน** | มีทางเข้าใบงาน โต๊ะโปรตีน งานตามเวลา และทีม เมื่อเปิดใบงานโปรตีน Agent เดินไปที่โต๊ะตามขั้น และเปิดประวัติการทำงานของตัวนั้นได้ | จัดเมนูให้เห็นงานปัจจุบันและปุ่มกลับใบงาน บนมือถือให้ย่อแผงรายละเอียดเพื่อเห็นโมเดลและแตะ Agent ได้ ทดสอบกรณี WebGL โหลดไม่สำเร็จ |
| **ใบงานโครงการ** | เลือกหรือสร้างโครงการ เริ่มจากโจทย์ ดูขั้นที่รอข้อมูล ส่งหลักฐาน และอ่านประวัติผู้ส่ง–ผู้รับ มีสิทธิ์เจ้าของและผู้อ่าน | หัวใบงานแสดงชื่อ รุ่น เจ้าของ และสิ่งที่ต้องทำต่อ ใช้ข้อความกำกับสถานะ เช่น “รอแนบสูตร” “พักเพื่อรอหลักฐาน” “รอหัวหน้าอนุมัติ” ผู้อ่านควรเห็นเหตุผลที่ตัดสินใจแทนเจ้าของไม่ได้ |
| **แผนวิจัยหกประเภท** | รองรับสังเคราะห์หลายขั้น ค้นคว้ายาและสูตรตำรับ ความคงตัว วิเคราะห์สารปนเปื้อน ตรวจสอบวิธีวิเคราะห์ และขยายขนาด ทุกขั้นผูกบทบาท หลักการ แหล่งอ้างอิง และผลที่ผู้ใช้บันทึก งานสังเคราะห์เลือกเรียงหรือขนานได้ งานความคงตัวกำหนดเดือนเก็บข้อมูลได้ | ใช้แผงรายละเอียดรายขั้นร่วมกัน แต่เปลี่ยนภาพรวมตามโจทย์ เช่น แสดงขั้นที่ต้องเสร็จก่อนสำหรับงานขนาน ปฏิทินสำหรับความคงตัว และตารางค่าซ้ำพร้อมหน่วยสำหรับงานตรวจสอบวิธี |
| **เปรียบเทียบสูตรและสถานีทดสอบ** | ใบงานแสดงสูตรตั้งต้นกับรุ่นเสนอ สัดส่วนที่เปลี่ยน ส่วนผสมที่ล็อก หลักฐานรายสาร และเหตุที่ขอตรวจซ้ำ สถานี 3D อ่านผลประเมินที่มีอยู่แล้วและมีการ์ดผลรายด้าน | ทำตารางก่อน–หลังที่สแกนได้เร็ว แสดงรุ่นและที่มาของผลทุกครั้ง แยก “ยังไม่มีผลประเมิน” “ข้อมูลขัดแย้ง” และ “รอเจ้าของตัดสินใจ” ค่าเริ่มต้นโครงการปิดการรัน QSAR ในเครื่อง คำตอบจาก OpenAI เป็นรายงานทบทวน จึงต้องมีป้ายคนละประเภทกับคะแนนจากโมเดล |
| **โต๊ะโปรตีนและหลักฐานอินซูลิน** | ดู GFP หรืออินซูลิน เลือกตำแหน่ง หมุน ซูม เทียบการจัดแนวด้วย RMSD และบันทึกท่ากับงานที่เชื่อมแล้ว อีกกรณีศึกษาเปรียบเทียบอินซูลินปกติกับ lispro มีขั้นของ Agent โครงสร้างอ้างอิง และหลักฐานการดูดซึมในคน | วางชื่องาน ผู้รับผิดชอบ และขั้นปัจจุบันไว้ข้างโมเดล ให้สลับดูรอบเก่าได้ แยกคำอธิบาย “ระยะในโครงสร้าง” กับ “ผลจากงานวิจัยในคน” พร้อมลิงก์ของแต่ละข้อ ค่า RMSD ใช้บอกความต่างของการจัดแนว |
| **ใบงานติดตามตามเวลา** | รับโจทย์ เป้าหมาย เงื่อนไข ตัวชี้วัด หน่วย ระยะเวลา และเกณฑ์พักงาน ระบบกำหนดเวลานัด รับค่าที่คนวัดพร้อมหลักฐาน และคำนวณผลต่างจากค่าที่บันทึก | หน้าแรกแสดงรอบถัดไปและปุ่มหลักหนึ่งปุ่ม หน้ารายละเอียดแสดงเวลานัดคู่กับเวลาบันทึกจริง ในกราฟหรือในตารางให้เว้นรอบที่ยังไม่มีค่า และแสดงหน่วยเสมอ |
| **ปัญหา คำตัดสิน และ LINE** | เมื่อรายงานปัญหาหรือค่าเกินเกณฑ์ ใบงานพักรอ เจ้าของเลือกติดตามต่อ เพิ่มรอบ หรือยุติพร้อมเหตุผล มีส่วนออกรหัสจับคู่ และตัวเชื่อม LINE แยกสำหรับแต่ละใบงาน | แสดงปัญหา รอบที่เกี่ยวข้อง และผลของแต่ละตัวเลือกไว้ด้วยกัน เพิ่มปุ่มคัดลอก URL ใบงานให้พี่แตม รหัสจับคู่ควรเปิดดูเฉพาะตอนใช้ ป้าย “ส่งแล้ว” ต้องอิงการตอบรับจากตัวเชื่อม ถ้าต้องเพิ่มข้อมูลสถานะ ให้ J ประสานก็อตและพี่แตม |
| **คลังอ้างอิงและไฟล์ของ Agent** | มีแหล่งตั้งต้นตามบทบาท ค้นงานวิจัยจาก Crossref และโครงการจาก GitHub เลือกใช้หรือพักแหล่งพร้อมเหตุผล แนบ PDF/TXT/MD/CSV/JSON ได้ไม่เกิน 10 MiB ต่อไฟล์ ต้นฉบับอยู่ใน R2 รายการอ้างอิงอยู่ใน D1 | การ์ดหนึ่งใบควรตอบได้ว่า “ใครใช้ อ้างหน้า/แถวไหน ช่วยข้อสรุปใด” แยกผลค้นใหม่ หลักฐานที่เลือกใช้ และสมมติฐาน แสดงกรณีค้นไม่พบ บริการค้นขัดข้อง หรือไฟล์ใหญ่เกินกำหนดข้างปุ่มที่ใช้แก้ |
| **ทีม Agent และรายงาน** | มีห้าบทบาท เครื่องมือประจำ ปุ่มดูผลเครื่องมือจากใบงาน ปุ่มส่งและติดตาม OpenAI session รวมถึงรายงานระบุรุ่นใบงาน บางผลเครื่องมือยังแสดงเป็น JSON | ทำการ์ดเลือกผู้รับผิดชอบและแสดงผลเป็นข้อมูลของบทบาทนั้น เช่น ตารางค่าของนักวิเคราะห์ แยก “ดูข้อมูลจากใบงาน” กับ “ส่งให้ OpenAI” แสดงสถานะพร้อมใช้ กำลังทำงาน กุญแจใช้ไม่ได้ หรือสิทธิ์ไม่พอ ให้กลับมาติดตาม session เดิมได้ |

## 3. ตำแหน่งของ Agent และข้อมูลที่ควรแสดง

ตารางนี้ใช้กับ **ใบงานตามเวลาบน Cloud** ใช้รหัสบทบาทเดียวกับตัวละคร 3D ส่วน Studio ของทีมมีชื่อผู้เชี่ยวชาญเฉพาะโดเมน เช่น Chemical Data Curator และ QSAR Model Scientist ให้ใช้ชื่อที่ตรงกับบริบทของหน้า โดยจับคู่ข้อมูลด้วยรหัสบทบาทเดิม

| Agent | เครื่องมือประจำใบงานตามเวลา | เมื่อผู้ใช้กดดูงาน ควรเห็น |
|---|---|---|
| หัวหน้าแล็บ · `director` | `read_study_plan` | โจทย์ เป้าหมาย เวลาแต่ละรอบ เกณฑ์พักงาน และงานที่จะส่งต่อ |
| นักวิจัย · `researcher` | `read_reviewed_sources` | หลักฐานที่เลือกใช้ ข้อที่แต่ละแหล่งรองรับ และสิ่งที่ยังหาคำตอบไม่ได้ |
| นักพัฒนาสูตร · `formulator` | `read_sample_conditions` | เงื่อนไขของตัวอย่าง รุ่นสูตร ตัวชี้วัด หน่วย และเกณฑ์ที่กำหนด |
| นักวิเคราะห์ · `analyst` | `compare_observations` | ค่าตั้งต้น ค่าที่วัดแต่ละรอบ ผลต่าง หน่วย และรอบที่รอข้อมูล |
| ผู้ประเมิน · `evaluator` | `check_evidence_gaps` | รอบที่ขาดหลักฐาน ค่าที่ติดเกณฑ์ และคำถามที่ต้องให้เจ้าของตัดสินใจ |

## 4. ลำดับส่งหน้าจอและเกณฑ์รับงาน

| ลำดับที่เสนอ | คนรับช่วง | ลองด้วยเคสนี้ก่อนส่ง |
|---|---|---|
| 1 · ใบงานตามเวลาและรายงาน | J ทำหน้าจอ · ก็อตตรวจฟิลด์และสถานะ | เปิดใบงาน “ติดตามการเปลี่ยนสี” กำหนดรอบ 0, 1, 24 และ 48 ชั่วโมง บันทึกค่ารอบแรกพร้อมหน่วยและหลักฐาน รีเฟรชแล้วยังเห็นค่าจริง และรอบในอนาคตยังแสดงว่ารอวัด |
| 2 · พักงานและตอบผ่าน LINE | J ทำแผงรอคำตอบ · พี่แตมกับพี่โอ๊ตทดสอบการเชื่อม | แจ้งปัญหาในใบงาน จับคู่ LINE ของผู้ทดสอบ ตอบให้เพิ่มรอบพร้อมเหตุผล แล้วกลับมาเห็นคำตัดสินเพียงครั้งเดียวในใบงานเดิม ทดสอบบนช่อง LINE จริงแยกจากผลทดสอบจำลอง |
| 3 · ทีมและคลังหลักฐาน | J ทำการ์ดบทบาทและการ์ดหลักฐาน · ก็อตตรวจสัญญาข้อมูล | เลือกนักวิจัย แนบเอกสาร ระบุหน้าและเหตุผล เปลี่ยนไปอีกใบงานแล้วไม่พบไฟล์ของใบแรก ทดสอบทั้งการดูผลเครื่องมือและสถานะยังไม่พร้อมเรียก OpenAI |
| 4 · ใบงานโครงการและโต๊ะ 3D | J ปรับการนำทางและมือถือ · ก็อตตรวจประวัติ | เปิดใบงานอินซูลิน ไปที่โต๊ะ แตะ Agent อ่านหลักฐาน แล้วกลับใบงานเดิมได้ เปิดแท็บกราฟของ Studio และคำถาม Agent เดิมได้หลังรวมงาน |
